# Decision log and handoff

Updated 2026-10-20.

## Decisions

- Select Tari standalone RxT / XTM-RX through a pool explicitly supporting XMRig `rx/0`; do not use Monero RxM or a Monero wallet for the first route.
- Pin XMRig v6.26.0 at `b2ca72480c58d197e18c885d9fc1a0c8d517e60a`. The selected pool publishes the `rx/0` invocation, and Tari's compatibility commit changed RandomX formatting for XMRig-compatible work.
- Use a public Tari payout address supplied by the tester only when live pool validation is ready. Never request a seed phrase or private key. Do not hard-code a sample address.
- Require Stratum TLS CA-chain and hostname verification. The narrow patch is `patches/0001-xmrig-stratum-tls-ca-host-verify.patch`; use Termux/OpenSSL CA roots and fail closed when missing. Local TLS tests have only run on host Linux.
- Termux launch defaults are one mining thread, RandomX light mode, no huge pages, verified TLS, and XMRig's upstream 1% donation. Preflight requires 512 MiB `MemAvailable` for light mode and 3 GiB for opt-in fast mode. These are system-level heuristics, not process limits or safety guarantees.
- Prevent duplicate sessions across source copies in the same Termux installation with an atomic lock at `$PREFIX/var/lib/xtm-miner/miner.lock`. Signal handling forwards INT/TERM/HUP and waits for the child before cleaning up its private config. A stale lock fails closed and requires process inspection before removal.
- Keep work staged: prove the ARM64 native engine and stop behavior before APK/JNI or dashboard work.
